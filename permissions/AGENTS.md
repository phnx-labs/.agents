# permissions/ — maintenance contract

Humans start at [README.md](./README.md).

Canonical permission rules for every agent, authored once in YAML. The canonical format is
**Claude's syntax**; `agents-cli` translates it per agent.

## Never edit default.yaml

`default.yaml` is generated by `build.sh` concatenating `groups/*.yaml` alphabetically. Edit
a group, then run `bash build.sh`. A hand edit to `default.yaml` is erased by the next build
and reads later as a mystery regression.

## Rule syntax

```yaml
# Blanket allow — permits ALL uses of a tool
- "Bash"
- "Read"

# Prefix match — the command must start with the prefix
- "Bash(git status:*)"       # git status, git status --short
- "Bash(npm run:*)"          # npm run build, npm run test

# Path rules — glob patterns for file tools
- "Write(~/.claude/*)"       # single level
- "Edit(~/.agents/**)"       # recursive

# Domain rules
- "WebFetch(domain:docs.rs)"

# MCP tools — exact tool name
- "mcp__Swarm__Spawn"
```

Deny rules use the same syntax under a `deny:` key. **Deny beats allow**, always.

## Cross-agent translation

| Canonical (YAML) | Claude (`settings.json`) | OpenCode (`opencode.jsonc`) | Codex (`config.toml`) |
|---|---|---|---|
| `"Bash(git status:*)"` | same | `{ "git status *": "allow" }` | inferred mode |
| `"Read"` | same | n/a — no read gating | n/a |
| `"WebFetch(domain:x.com)"` | same | n/a | `network_access: true` |
| `deny: "Bash(sudo:*)"` | same | `{ "sudo *": "deny" }` | forbidden prefix rule in `.codex/rules/agents-deny.rules` |

Codex permission resources still translate allows coarsely, while denies become
forbidden prefix rules. Native launches use agents-cli's named `agents-plan` and
`agents-edit` permission profiles: both enable network and request approvals on demand;
plan extends Codex's read-only profile, while edit extends the workspace profile and adds
`~/.agents` plus regenerable build caches. A rule that depends on Claude's fine-grained
syntax can still widen on Codex — check the translation before relying on a narrow allow.

## Group numbering

| Range | Purpose |
|---|---|
| `00` | Header, plus `00-local.yaml` (gitignored, machine-specific) |
| `01-15` | Bash allows, ordered core → per-language → tooling → misc |
| `20-29` | WebFetch domain allowlists |
| `30` | Blanket allows plus Write and Edit path rules |
| `99` | Deny lists — `99-deny.yaml` and the stricter `99-deny-sandbox.yaml` |

## Rules for anything checked in

- Use `~` for home. Never `/Users/<name>` or `/home/<name>` — it breaks on every other machine.
- Allow **tool names**, never absolute paths to binaries.
- A rule that only makes sense on one machine goes in `00-local.yaml`, which is gitignored.
- Widening a deny list is a security change. Say so in the PR body and name what it now permits.

## Adding a permission

1. Edit the right file in `groups/`. Do not create a new group unless the category is
   genuinely new.
2. `bash build.sh` to regenerate `default.yaml`, and commit the regenerated file.
3. If you added a group file, add its row to the table in [`README.md`](./README.md).
4. Add a `CHANGELOG.md` entry under the next version.

## This file is not synced into agent context

`CLAUDE.md` and `GEMINI.md` here are symlinks to this file, so an agent working *in this
directory* reads it. It is **not** injected into every agent's prompt — only `rules/` is
(`profiledKind` maps `rules` -> `'memory'`, `apps/cli/src/lib/resources.ts:64-65`). Write for the agent
editing permissions, not for every agent on the fleet.
