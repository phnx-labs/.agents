# permissions/ — maintenance contract

Humans start at [README.md](./README.md).

Canonical permission rules for every agent, authored once in YAML. The canonical format is
**Claude's syntax**; `agents-cli` translates it per agent.

## Never edit default.yaml

`default.yaml` is generated by `build.sh` concatenating the groups listed by
`presets/default.yaml`, in manifest order. `00-local` is intentionally omitted from the
committed output. Edit a group or the preset, then run `bash build.sh`. A hand edit to
`default.yaml` is erased by the next build and reads later as a mystery regression.

## Rule syntax

```yaml
# Blanket allow — permits ALL uses of a tool
- "Bash"
- "Read"

# Prefix match — the command must start with the prefix
- "Bash(git status:*)"       # git status, git status --short
- "Bash(npm run:*)"          # npm run build, npm run test

# Path rules — glob patterns for file tools
- "Write(~/.claude/*)"       # single level
- "Edit(~/.agents/**)"       # recursive

# Domain rules
- "WebFetch(domain:docs.rs)"

# MCP tools — exact tool name
- "mcp__Swarm__Spawn"
```

Deny rules use the same syntax under a `deny:` key. Where the target harness supports that
tool rule, deny beats allow.

## Boundary of this policy

- Blanket `Bash`, `Read`, `Write`, and `Edit` rules remove ordinary harness approval prompts.
  The command-substitution/simple-expansion and cd-before-git prechecks run ahead of allow
  rules and can still prompt.
- Credential `Read`/`Edit`/`Write` denies reduce accidental file-tool access. They are not a
  secrecy boundary: allowed Bash commands can still read or change the same paths.
- Git, removal, merge, main-branch, and secrets hooks are cooperative guardrails for normal
  agent behavior. They are not an adversarial sandbox or operating-system security boundary.

## Cross-agent translation

| Canonical (YAML) | Claude (`settings.json`) | OpenCode (`opencode.jsonc`) | Codex (`config.toml`) |
|---|---|---|---|
| `"Bash(git status:*)"` | same | `{ "git status *": "allow" }` | inferred mode |
| `"Read"` | same | `{ "*": "allow" }` | n/a |
| `"WebFetch(domain:x.com)"` | same | n/a | `network_access: true` |
| `deny: "Read(~/.ssh/**)"` | same | `{ "~/.ssh/**": "deny" }` | n/a |

Codex permission resources still translate command allows coarsely and command denies into
forbidden prefix rules; file-tool rules such as the credential deny above have no Codex
equivalent. Native launches use agents-cli's named `agents-plan` and
`agents-edit` permission profiles: both enable network and request approvals on demand;
plan extends Codex's read-only profile, while edit extends the workspace profile and adds
`~/.agents` plus regenerable build caches. A rule that depends on Claude's fine-grained
syntax can still widen on Codex — check the translation before relying on a narrow allow.

## Group numbering

| Range | Purpose |
|---|---|
| `00` | Header, plus `00-local.yaml` (gitignored, machine-specific) |
| `01-15` | Bash allows, ordered core → per-language → tooling → misc |
| `20-29` | WebFetch domain allowlists |
| `30` | Blanket Bash, Read, Write, and Edit allows |
| `99` | One canonical credential file-tool matrix shared by default and sandbox presets |

## Rules for anything checked in

- Use `~` for home. Never `/Users/<name>` or `/home/<name>` — it breaks on every other machine.
- Allow **tool names**, never absolute paths to binaries.
- A rule that only makes sense on one machine goes in `00-local.yaml`, which is gitignored.
- Changing a deny list changes accidental-access behavior. State exactly which tool/path pairs change.

## Adding a permission

1. For an existing category, edit its file in `groups/`; then run `bash build.sh` to
   regenerate `default.yaml` and `bash permissions_test.sh`.
2. Create a group only for a genuinely new category. Add its name to both
   `presets/default.yaml` and `presets/sandbox.yaml` unless the group is intentionally
   preset-specific, and document that scope in the group table in [`README.md`](./README.md).
3. For a new group, run `bash build.sh` to regenerate `default.yaml`, then run
   `bash permissions_test.sh` to prove both preset manifests resolve and generated output
   matches the default manifest.
4. Commit the regenerated `default.yaml` with the source change.
5. Add a `CHANGELOG.md` entry under the next version.

## This file is not synced into agent context

`CLAUDE.md` and `GEMINI.md` here are symlinks to this file, so an agent working *in this
directory* reads it. It is **not** injected into every agent's prompt — only `rules/` is
(`profiledKind` maps `rules` -> `'memory'`, `apps/cli/src/lib/resources.ts:64-65`). Write for the agent
editing permissions, not for every agent on the fleet.
