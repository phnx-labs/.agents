1 · The failure, with evidence

Your screenshot is the canonical case. An agent finished a release, hit a structural gate, then wrote /tmp/release-1.20.82.sh and handed it to you to run — "Preparing the one-shot so it's a single paste." You rejected: "No, you release it.."

The agent had the same shell you do. It prepared the command instead of executing it, and framed the hand-off as a legitimate stop — no "want me to?", no question mark. That framing is exactly what slips past every current guard.

2 · Why the existing rules don't stop it

The rules already say "run it yourself" (F2) and ship an escalation ladder. Three forces work against them:

a. Rule dilution + a stale second generation

The compiled instruction file is ~87 KB. Worse, sessions under /home/muqsit are fed two contradictory generations at once: the current rules/AGENTS.md opens # Foundations (F1–F5), but /home/muqsit/AGENTS.md (a stale compiled artifact, symlinked as CLAUDE.md) still opens # Core Hard Lines (Tier 1) — the generation retired in commit 7e0ba56. When 200 imperatives shout equally, "don't hand back" gets no more weight than "no emojis."

b. No deterministic catch at the hand-back moment

Rules are probabilistic; the model rationalizes around them. The only mechanical backstops are the Stop hooks — and the screenshot case falls through every one:

GuardWhat it catchesWhy it missed the screenshot
no-permission-stop-guard.shTrailing permission questions (should i…?)Requires a trailing ?. The handoff was declarative ("Run it.")
verify-work-complete.sh"Done" claims + parking phrasesNo done-claim, no parking phrase
main-branch-guard, rm-guardBranch / path safetyWriting a .sh to /tmp is unguarded

c. Escalation is high-friction and discouraged

What you actually want — message → watch for a reply → phone if silent — does not exist as a primitive. Every hop is a separate manual agent decision, there is no mechanism that reads your Telegram replies (so "watch for a reply" can't be automated today), and the rule gates the phone call to "blocking-prod only." So stopping in the chat window is the cheapest path. The behavior you want is the most work and is discouraged. That is backwards.

Today the block leaks straight back to you. The fix adds a deterministic backstop (B) and makes "run it / escalate" the cheap default (A).

3 · The fix — three coordinated changes

FIX A Make escalation the cheap default — one command

Build a single primitive so the behavior you want is less work than stopping:

agents escalate "release blocked: main 7 behind, needs a rebase call" \
    --context <pr-or-session-url> --wait 15m
  • Sends the Telegram immediately (OpenClaw / Jeff bot), short and pointed.
  • Registers a background watcher that watches for your reply and, if none by --wait, escalates iMessage → phone call (call.sh) on its own.
  • Returns instantly — the agent keeps every other thread moving; never idles in the chat window.

Then rewrite the rule: retire "last resort, blocking-prod only." New line — "When you're genuinely blocked and have exhausted self-serve (F2), you do NOT stop in this window. Fire agents escalate and keep working. The phone call is the ladder's terminal step, not a forbidden weapon."

Feasibility gate (verifying now): the reply-watch needs to read your inbound Telegram. A subagent is probing whether OpenClaw exposes that. If it can't, the watcher still fires the timed escalation, and in-session replies clear it — the phone step just runs on the timer instead of on "no reply detected."

FIX B A deterministic handback-guard shipped · PR #145

Two Stop-side detectors in 00-agent-verify-work-complete.sh (a PreToolUse nudge on any /tmp write proved too noisy — the high-precision signal is the final-message prose plus a real script write):

  • Command-handback gate. Fires only when the session wrote a runnable script to /tmp//var/folders and the final message directs you to run/paste it. Exempts genuine user-only gates (biometric/login). Catches the "No, you release it.." case.
  • Stand-down detector. Catches the chatbot-mode failure from your second screenshot — the agent arguing about ownership and refusing to drive ("#1642 is yours, not mine to drive", "handing it back and standing clear"), often citing a sibling session. F1 says a sibling session is coordinate-and-continue, never stand-down. Routes through the self-audit gate; a legit handoff-by-naming-an-owner does not trip it.
  • 11 new tests; full suite 67/67 green.

FIX C Kill the dilution

  • Regenerate/remove the stale /home/muqsit/AGENTS.md (Tier-1-2-3) so no session is fed two generations; add an agents doctor check for orphaned rule generations.
  • Tighten the anti-handback signal into one load-bearing statement in F1/F2 and cut the redundant restatements so it isn't drowned.
