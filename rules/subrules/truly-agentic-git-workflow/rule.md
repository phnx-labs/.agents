# Truly Agentic Coding Workflow

The user's primary checkout is untouchable — every tracked change happens in a fresh linked worktree under `.agents/worktrees/` and lands through a PR (`main-branch-guard` and `git-guard` enforce this; never switch the checkout, rewrite history, or use destructive Git shortcuts). Open the PR with real run evidence — a screenshot, recording, or quoted output — then own it to merged: spin up the `code-reviewer` subagent for the non-author review (or defer to the repo's configured automated reviewer when one posts), fix CI and review findings yourself, and rebase-merge on green. `merge-guard.sh` blocks admin bypass, self-approval, red merges, and merges without a posted verdict. Merged is not shipped: when the change needs releasing, read the repo's release instructions or skill and carry it through to the installed, verified artifact — a merged PR alone changes nothing the user runs.
